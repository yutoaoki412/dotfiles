# Dotfiles 運用・同期ワークフロー

本スキルは、dotfilesリポジトリ内で設定の変更、新規ツールの追加、Homebrewパッケージの管理、および整合性の検証を行う際の詳細手順を定義します。

---

## ワークフロー1: 既存設定の変更と反映

設定ファイルの変更は、実環境を先に編集してから取り込む方式と、リポジトリ内を直接編集して反映する方式のいずれかを用います。

### 手順
1. **リポジトリ内の対象ファイル編集**:
   - `dot_config/...` または `dot_zshrc` 等の該当ファイルを編集します。
2. **構文と動作の検証**:
   - Ghostty設定を変更した場合: `ghostty +validate-config` を実行し、構文エラーがないことを確認します。
   - シェル設定を変更した場合: サブシェル（`zsh -lic 'echo OK'`）で読み込みエラーが出ないことを確認します。
3. **実環境への反映**:
   - `chezmoi apply` を実行し、ホームディレクトリの設定を更新します。
4. **差分の確認**:
   - `chezmoi status` および `chezmoi diff` を実行し、意図した差分のみが適用され、未解決の差分が残っていないことを確認します。

---

## ワークフロー2: 新規ツールの設定追加

新しいCLIやGUIツールの設定をdotfilesの管理下に加える際の手順です。

### 手順
1. **設定パスの確認（XDG準拠）**:
   - 対象ツールが `$XDG_CONFIG_HOME`（`~/.config/<tool>/`）に対応しているか確認します。
   - 対応している場合は必ず `dot_config/<tool>/...` のパスに配置します。
2. **パーミッションとテンプレートの選定**:
   - 秘密情報を含まない一般的な設定ファイルには `private_` を付与しません（通常の `dot_` のみ）。
   - マシン固有のメールアドレスや環境変数に依存する場合は `.tmpl` サフィックスを付与し、chezmoiテンプレート構文（`{{ .email }}` 等）を使用します。
3. **安全性の検証**:
   - トークンや認証情報が平文で含まれていないか必ず精査します。
4. **反映と適用確認**:
   - `chezmoi apply` を実行し、対象のパスに意図通りのパーミッションと内容で展開されたことを確認します。

---

## ワークフロー3: Homebrewパッケージ（Brewfile）の更新

開発ツールやGUIアプリケーションの導入状況を `Brewfile` に同期する手順です。

### 手順
1. **Brewfile の直接編集またはダンプ**:
   - 特定のツールを追加する場合: `Brewfile` の該当セクション（CLI Tools、GUI Applications、Fonts等）に `brew "..."` または `cask "..."` を直接追記します。
   - 現在の環境全体から更新する場合:
     ```bash
     brew bundle dump --force --file="$(chezmoi source-path)/Brewfile"
     ```
2. **過剰・環境依存パッケージの整理**:
   - ダンプを行った場合、マシン固有の一時的パッケージや不要なVS Code拡張が混入していないか差分を確認します。
   - GUIアプリケーションには対応する設定（Ghostty、Zedなど）が存在するか確認します。
3. **整合性チェック**:
   ```bash
   brew bundle check --verbose --file=Brewfile
   ```
   依存関係が満たされていることを確認します。

---

## ワークフロー4: コミット前整合性チェックリスト

Gitコミットを行う前に、以下の4項目を必ず検証します。

1. **chezmoi状態の確認**:
   - `chezmoi status` を実行し、想定外の未反映ファイル（`M` や `MM`）がないこと。
   - `chezmoi diff` の出力が空（完全同期状態）であること。
2. **.chezmoiignore の維持確認**:
   - リポジトリ管理用ファイル（`README.md`、`Brewfile`、`AGENTS.md`、`.envrc` 等）がホームディレクトリ直下に誤って展開されていないこと。
3. **秘密情報の検査**:
   - `git diff` を目視確認し、秘密鍵、トークン、またはハードコードされた個人パス（`/Users/aokiyuto/...`）が含まれていないこと。
4. **コミットメッセージの規格**:
   - Conventional Commits（`feat:`, `fix:`, `chore:`, `docs:` 等）に準拠したメッセージを作成します。
