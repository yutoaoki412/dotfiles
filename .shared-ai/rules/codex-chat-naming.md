# Codex Desktopのチャット名

Desktopの親チャットでは、新規・再開後の最初の依頼、主題や成果物の変更、ユーザーまたは外部の対応待ち、完了報告の直前に、現在の件名と実際の作業を照合する。短い依頼は回答時にまとめて更新してよい。

命名判断は `gpt-6.1-terra` の専用サブエージェントに委任する。親は現在の件名・依頼・結果・待ち先の短い要約だけを渡す。最初は `spawn_agent` で `fork_turns="none"` とモデルを明示し、同じチャットで利用できる担当は `followup_task` で再利用する。担当はツールを使わず件名案だけを返す。命名担当を含むサブエージェントにはこの委任・改名ルールを適用しない。

件名は「状態の絵文字 対象と目的」の短い日本語にする。🔵はCodexの作業中、🙋はユーザーの判断・入力・操作待ち、⏳は外部の回答・処理・開始時刻待ち、✅は直近の依頼が完了した状態を表す。定期チャットでは直近回を基準にする。状態だけが変わったら絵文字だけを替える。過去の状態が判断できなければ件名だけ整える。ユーザー指定の件名、【日次】、Issue番号は保つ。

分類を特定できるときは「状態の絵文字 【分類】対象と目的」とし、親は命名担当に依頼元と主題も伝える。JIRAチケットで受けた個別の取り込み依頼（列追加を含む）は【JIRAチケ】、取り込み依頼刷新PJの設計・実装・検証・進捗整理は【取り込み依頼刷新PJ】、Slackの #i3-gcp-lookerで受けた問い合わせは【問い合わせ対応】とする。複数に該当するときは個別のJIRA依頼、刷新PJの成果物、問い合わせの順に主題を示す分類を1つ選ぶ。参考リンク・作業ログ・投稿先として登場しただけのチャンネルは依頼元に数えない。根拠がないときは分類を省く。既存の【日次】などの用途表示は残す。

親が案を会話と照合し、差分がある場合だけ Desktop の `set_thread_title` で自分のチャットを更新する。強制終了などで古くなった表示は再開時に合わせる。
